## Current behaviour

fetchLoanInterestTransactions scopes standalone interest transactions solely by interestCategoryId + sourceAccountId. When two loans are active concurrently and share both fields, each loan's fetch returns both loans' interest transactions, cross-attributing interest in both directions. The comment at line 1065 documents this and says 'give each loan its own interest category to keep them apart.'

## Proposed behaviour

Interest transactions fetched for a loan are restricted to those that belong exclusively to that loan, so concurrent loans that happen to share the same interest category and payment account are not merged.

## Alternatives

Option A (recommended for correctness): Add a persisted loanAccountId (or equivalent tag) to standalone interest transactions. Requires a database migration and schema change. Option B (product-level): Validate at the loan-settings UI that no two active loans share the same interestCategoryId + sourceAccountId, and surface a clear error so the user assigns distinct categories. Requires no DB change but constrains user workflow. Option C (rejected): Re-introduce a date lower bound per loan. Was deliberately removed to support grace periods and pre-start-date migrated history; would regress REV-20260803-033.

## Recommendation

Option A produces the most correct long-term data model and removes the user-facing configuration constraint entirely. Option B is lower risk and deployable without a migration, but it is a user-workflow change and leaves existing misconfigured loan pairs unresolved until the user corrects them. Decide which risk profile fits the current release window.

## Risks

Option A: requires a migration; existing standalone interest transactions have no loanAccountId and would need a backfill or a UI step to associate them. Option B: existing users who already share a category between concurrent loans see no fix — only future configuration is blocked. If neither option is implemented, concurrent loans sharing a category silently double-count interest with no visible error.
