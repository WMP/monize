## Location

`backend/src/accounts/accounts.service.ts:743`

## Failure scenario

The update assigns any valid payee UUID directly, and account creation similarly spreads the DTO into the entity. An authenticated user who supplies another user's payee UUID can create a cross-tenant account-to-payee relationship because the foreign key checks only existence. Deleting that other user's payee will then modify the attacker's account through ON DELETE SET NULL.

## Recommended fix

Before create or update, query the payee by both id and userId, using the QueryRunner manager during updates, and reject IDs not owned by the requester.
