## Location

`frontend/src/components/accounts/AccountForm.tsx:513`

## Failure scenario

The category and payee handlers store a cleared selection as `''` (lines 515, 527, and 532), and clearing the registered memo input also produces `''`. The production submit cleanup removes empty strings before PATCH rather than converting these fields to `null`, so the database retains the old `interestCategoryId`, `overpaymentCategoryId`, `overpaymentPayeeId`, or `overpaymentMemo`. For example, clearing an overpayment category from an existing mortgage and saving leaves that category active, causing later ordinary transactions in it to be treated as 100% principal.

## Recommended fix

Allow null in the form schema and convert cleared recognition fields to `null` during edits; use `undefined` only for unset fields during creation.
