## Location

`frontend/src/components/accounts/loan-detail/LoanDetailView.tsx:138`

## Failure scenario

Lines 138-140 call computePastImpact even when baseline is null. For an outstanding $80,000 loan with principal, rate, frequency, start date, and amortization configured but paymentAmount unset, projectionInput and baseline are null while computePastImpact can still construct the original schedule. The null current projection contributes zero remaining interest, so PastImpactSection reports most of the loan's future contractual interest as “Interest Already Saved” even though the debt remains outstanding.

## Recommended fix

For an outstanding loan, compute or display past impact only when a complete, paid-off-capable baseline exists. Otherwise return null; reserve a null current projection for loans that are actually paid off.

## Re-review of `ba5ecca29773`

Not fixed. `remainingImpactKnown` checks only that `currentProjection` is non-null, not that it reached payoff. For example, an outstanding $80,000 loan at 6% with a $500 monthly payment can have a future rate change to 10% without a payment adjustment. `generateLoanSchedule` returns a non-null result with `paidOff: false` after the payment stops covering interest. This code nevertheless subtracts only that truncated schedule's accumulated interest and treats all later interest as zero, reporting the difference from the complete contractual schedule as interest already saved. It also reports zero months saved because the incomplete projection has no payoff date.
