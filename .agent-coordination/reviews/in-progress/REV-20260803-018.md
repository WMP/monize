## Location

`frontend/src/components/accounts/loan-detail/useLoanRateEditing.ts:157`

## Failure scenario

The pending preview is cleared before applyScheduledPayment completes and is not restored in the catch block. If the request fails due to a transient network or server error, the rate change remains saved and the linked scheduled bill remains stale, but the confirmation dialog disappears and cannot be retried—even after reloading, because the preview is returned only by rate-change creation.

## Recommended fix

Keep the preview while the request is pending and clear it only after success or explicit skip; add a separate loading flag to prevent duplicate confirmation clicks.
