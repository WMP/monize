## Location

`frontend/src/components/accounts/loan-detail/LoanRateControls.tsx:42`

## Failure scenario

Lines 42-48 provide only onDateChange. The shared DateInput's touch/browser mode reports native selections through onChange, while its desktop/browser mode does not call onDateChange when the field is cleared. On a touch device using the default browser date format, selecting a date leaves form.effectiveDate unchanged and Save disabled. On desktop, clearing a previously selected date leaves the old date in form state, so saving records the rate change—and potentially recalculates a scheduled payment—on the stale date despite the input appearing empty.

## Recommended fix

Make DateInput invoke onDateChange for both selections and clears in every mode, or wire a shared effective-date handler to both onChange and onDateChange. Add coverage for touch/browser selection and desktop/browser clearing.
