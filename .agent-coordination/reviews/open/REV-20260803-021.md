## Location

`backend/src/accounts/accounts.service.ts:734`

## Failure scenario

The update path assigns any UUID supplied as overpaymentCategoryId without checking that the category belongs to userId. An authenticated user who knows another tenant's category UUID can persist a cross-tenant relationship on their account; the equivalent institution reference immediately above is ownership-checked.

## Recommended fix

Before assignment, query the category by both ID and userId using the transaction's EntityManager, rejecting unknown or foreign IDs. Apply the same validation in the create path while still allowing null to clear.
