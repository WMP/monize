## Location

`frontend/src/components/accounts/loan-detail/PayoffComparisonChart.tsx:240`

## Failure scenario

PayoffComparisonChart receives no currency code, and the new overpayment annotation calls formatCurrencyCompact without one. If the user's default currency is USD while the displayed loan is denominated in EUR, a recorded €1,000 overpayment is shown as $1,000.

## Recommended fix

Add a currencyCode prop, pass the account's currency from the caller, and supply it to the tooltip and axis currency formatters.

### fix-agent 2026-08-03 -- fixed in `77daf96c`

Confirmed real at `main` `4e48a767`: the chart had no `currencyCode` prop at all,
so the y-axis ticks, the tooltip's balance line and the overpayment annotation
all fell back to the user's default currency.

Added `currencyCode` as a **required** prop rather than optional-with-default, so
the compiler names any unfixed call site instead of the next one silently
reintroducing this. It did: five renders in the chart's own test file failed the
build until updated. `LoanDetailView` passes `account.currencyCode`, matching the
`AmortizationScheduleTable` call directly beneath it.

The y-axis needed a wrapper, not `tickFormatter={formatCurrencyAxis}`: recharts
calls a tickFormatter as `(value, index)`, so by-reference hands it the tick
index as the currency argument. `formatCurrencyAxis`'s `string | number` second
parameter absorbs that instead of failing on it, which is why nothing flagged it.

**Worth your attention:** the test file's recharts mock had `YAxis: () => null`
and `Tooltip: () => null`, so neither the tick formatter nor the tooltip content
ever ran -- no test could have caught this finding. Both now render their
formatters' output, with YAxis passing a tick index second exactly as recharts
does. The `useNumberFormat` mock also discarded the currency argument; it now
mirrors the real fallback.

Both new tests verified failing with the component reverted. Checks: lint (1
pre-existing Combobox warning), type-check, i18n:check, full frontend suite. No
catalog change. Backend untouched. No `test:integration`/`e2e` -- no Postgres, no
browsers here.
