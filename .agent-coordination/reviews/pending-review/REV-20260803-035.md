## Location

`frontend/src/lib/loan-history.ts:391`

## Failure scenario

Separate interest is consumed once per date, but subsequent regular payments on that date fall back to analyticInterest. If an overpayment and a regular principal transfer share a date and the overpayment sorts first, it consumes the one actual interest expense; the regular row then adds a second analytic interest amount. Reversing the input order produces only the actual amount, so cumulative interest depends on transaction ordering.

## Recommended fix

Resolve all payments for a date as a group, assign the actual interest to the appropriate regular payment, and suppress analytic fallback for other rows covered by that same charge.
