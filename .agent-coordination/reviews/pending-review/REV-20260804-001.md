## Location

`backend/src/accounts/loan-payment-detector.service.ts:326`

## Failure scenario

Every non-transfer categorized split is treated as interest, and each matching iteration overwrites the previous amount. For a $1,000 payment split into $850 principal, $100 loan interest, and $50 insurance, an iteration order with insurance last records $50 as interest and infers roughly half the real rate. No comparison is made with the account's configured interest category.

## Recommended fix

Use only splits in the configured interest category and aggregate all matching legs using the repository's 4-decimal money helpers. When no category is configured, accept split interest only when the categorized leg is unambiguous.
