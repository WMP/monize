## Location

`frontend/src/components/accounts/AccountForm.tsx:762`

## Failure scenario

`LoanFields`, which now contains the interest-booking and overpayment-recognition controls, is rendered only when `!account`. Editing an existing `LOAN` therefore exposes none of these controls, while mortgages do. For example, a user with an existing loan whose standalone overpayments are identified by memo cannot configure that memo or select `SEPARATE` interest booking; those payments continue to be split incorrectly in schedules and projections.

## Recommended fix

Render the recognition controls for existing loans. Either make `LoanFields` accept an edit mode that hides only payment-setup inputs, or render `OverpaymentRecognitionFields` separately when editing a loan.
