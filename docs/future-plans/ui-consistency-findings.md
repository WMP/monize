# UI consistency findings (follow-up to kenlasko/monize#1912)

Status: final draft for maintainer review. Scope: `frontend/src` on `main` at 5c550520 (WMP/monize; upstream `main` differs only in backend and loan files), compared with `docs/frontend/screens-and-dialogs.md` from PR #1912. Method: a source read (grep plus reading the matched code); spot checks of each section by hand; no screen was run in a browser. Counts are approximate.

This file collects:

1. **Contradictions** between the document and its own reference screens (decide these first).
2. **Candidate rules** that the reference screens follow but `docs/frontend/screens-and-dialogs.md` does not state yet.
3. **Deviations**: screens that detract from the whole, because they break a rule from `screens-and-dialogs.md` or a candidate rule.

Each item names the evidence (`file:line`, relative to `frontend/src/`). Each item needs human review before it becomes a rule or a fix.

## Suggested priority

These are more than looks; they are defects a user can meet:

1. **D41**: an AI provider and a push device are deleted on one click, with no confirmation.
2. **D29**: six reports probably drop their date controls (and focus) on every reload. Not reproduced in a browser.
3. **D18**: `<Link><Button>` nests a button in a link on five report pages (accessibility).
4. **D27**: hard-coded English "Cancel" in settings, outside i18n.
5. **`Modal` title header** (first contradiction below): one change in `components/ui/Modal.tsx` aligns 30 dialogs (D1) and gives New Transaction an accessible name.

## The reference screens contradict the document

Before anyone fixes a screen "against" `screens-and-dialogs.md`, a maintainer must decide, rule by rule, whether the document or the reference code is correct. As written, several rules fail the screens the document names as the model (all verified in the source):

- **Segmented filter.** The document says `SEGMENTED_GROUP_CLASS` + `segmentClass`. No reference screen uses it: `app/currencies/page.tsx:315-337` and `app/securities/page.tsx:420-442` hand-roll `bg-blue-600` buttons (with counts); `components/accounts/AccountList.tsx:788-819` and `components/transactions/TransactionFilterPanel.tsx:511-545` hand-roll them without counts. Only newer screens use the constant (`AiReviewInbox`, `EmailReceiptsManager`, `InvestmentViewToggle`).
- **Table cells.** The document names `CurrencyList` and `SecurityList` as models "with `Th`/`Td`". Both use raw `<th onClick>` + `SortIcon` (`components/currencies/CurrencyList.tsx:610-616`, `components/securities/SecurityList.tsx:601-643`). The `<th onClick>` is also not reachable by keyboard. The header class string is hand-copied on every reference list (TransactionList 11, HoldingsList 6, InvestmentTransactionList 10, CurrencyList 5, SecurityList 4, AccountList 2 raw `<th>`); none uses `Th` or `TH_CLASS`.
- **Toolbar wraps.** Currencies and Securities use `flex flex-col sm:flex-row` without `flex-wrap` (`app/currencies/page.tsx:307`, `app/securities/page.tsx:412`).
- **Refresh.** Currencies "Refresh Rates" has no icon and no age (`app/currencies/page.tsx:281-287`). Securities puts Refresh in the toolbar row (`app/securities/page.tsx:446-452`), Investments in `PageHeader` (`app/investments/page.tsx:253`).
- **Transactions.** No `SummaryCard` row (a chart, `app/transactions/page.tsx:1304`); filters fold into a Show/Hide panel (`TransactionFilterPanel.tsx:249-290`), which the "filters are always visible" rule forbids; the search field has a label and comes last (`TransactionFilterPanel.tsx:764-771`).
- **Investments.** Three primary "New" buttons on one screen: `NewTransactionButton` in `PageHeader` (`app/investments/page.tsx:258`) and two hand-rolled `bg-blue-600` buttons (`components/investments/InvestmentTransactionList.tsx:608-614`, `app/investments/page.tsx:438`). Brokerage / Cash is a segmented control that switches registers, i.e. navigation (`InvestmentViewToggle.tsx:36-44`, key `brokerageTab`), which the document reserves for `Tabs`. Filters are behind toggles (`InvestmentTransactionList.tsx:618-646`).
- **Accounts.** No toolbar above the list; search comes last inside the list card (`AccountList.tsx:834-840`); no `Pagination`.
- **Export.** Currencies, Securities and Accounts have none. `ListTopToolbar` has no export control of its own (`components/ui/ListTopToolbar.tsx:40`); Transactions passes a button through `actions` (`TransactionList.tsx:750-754`). The rule "Export is the export control of `ListTopToolbar`" names a control that does not exist.
- **Security detail order** is header, `SummaryCard`s, a chart grid, then `Tabs` (`app/securities/[id]/page.tsx:444, 464, 509`), not "`SummaryCard` row, then `Tabs`".
- **`PageHeader` help** is shown only on hover at `md` and up (`components/layout/PageHeader.tsx`, `md:group-hover`), against the rule that help is not hidden below a breakpoint.

- **The reference dialog has no accessible name.** New Transaction draws its own `h2 text-2xl font-bold mb-4` as the first child and does not pass `title` to `Modal` (`app/transactions/page.tsx:1504-1506`), so it has no `aria-labelledby`. The dialogs that do pass `title` get the name but also the drifted header: `h2 text-lg font-semibold` in a `border-b` strip with an `XMarkIcon` close button (`components/ui/Modal.tsx:404-428`); `footer` adds a `border-t` strip (`:448`). Today a dialog can look right or be named, not both. The real fix is in `Modal`: draw the `title` as the New Transaction heading (no strip, no X) and keep `aria-labelledby`. Then all 30 titled dialogs and New Transaction converge.
- **`ConfirmDialog` and `UnsavedChangesDialog` break the dialog rules for all 61 confirmations**: `h3 text-lg font-medium` title (`components/ui/ConfirmDialog.tsx:108`, `UnsavedChangesDialog.tsx:35`) and raw `<button>`s with hand-written colour classes instead of `<Button variant="primary|danger">` (`ConfirmDialog.tsx:116-121`, `UnsavedChangesDialog.tsx:50-55`). Decide whether a confirmation is an exempt dialog kind (smaller title, question paragraph) and write that down.

- **"Short prepositions stay lower case" is not defined, and the document's own example breaks it**: "Funds From (optional)" (`investments.json:265`) capitalises "From", while "Price per Share" lowers "per". Say what "short" means (for example three letters or fewer) and whether a phrasal particle ("Group By", "Sort By") counts.
- **Title Case labels describe only part of the app.** About 444 field labels are Title Case and 206 are sentence case, in whole feature areas (auth, import, email receipts, rules, GEM, warranties, Monte Carlo, loan detail). This is a split, not drift at the edges; a rule needs a migration plan, not only a sentence.
- **The ellipsis in the document ("…") is not the app's**: "..." is used 247 times, "…" 16 times (e.g. `securities.json:13` "Search by symbol or name...").

Suggestion: either fix the reference screens first (they are what agents copy), or narrow the document to what those screens do today and list the gaps as known debt.

## Candidate rules

### List and detail pages

- **R1. Page container: `<main className="px-4 sm:px-6 lg:px-12 pt-6 pb-8">` at full width** (`app/currencies/page.tsx:274`, `securities:392`, `transactions:1291`, `investments:232`); settings pages `max-w-4xl mx-auto`.
- **R2. Every list page passes `helpUrl` to `PageHeader`** (Currencies, Securities, Transactions, Investments, Accounts).
- **R3. The list sits in `${CARD_CLASS} overflow-hidden`, with `<LoadingSpinner text>` inside it while loading** (`currencies:368-370`, `securities:471-473`, `transactions:1709-1712`).
- **R4. `EmptyState` renders inside the list component** (`CurrencyList.tsx:549`, `AccountList.tsx:773`).
- **R5. Sort: a sortable header with `SortIcon` and `aria-sort`, persisted with `useLocalStorage('monize-<list>-sort-field' / '-sort-dir')`, and a sort, filter or search change resets to page 1** (`currencies:53-54, 242-260`). Status filters start at `'active'` (`currencies:51`, `securities:65`).
- **R6. Density: `useDensityPreference(view)` with `DensityToggleBar` above a table, or `DensityToggle` in `ListTopToolbar` for a register** (`CurrencyList.tsx:487, 566`).
- **R7. Phone layout: `wrapped = isMobile && density === 'normal'` renders one card cell per row with a slim sort header** (`CurrencyList.tsx:523, 571-600`, also Security, Account, Payee, Institution, Warranty lists); a register uses `useRegisterPhoneCard`.
- **R8. Number, rate and action columns are right-aligned; row actions are `RowActions`.**
- **R9. A list reloads after undo/redo and AI actions with `useOnUndoRedo(load)` + `useOnAiAction(load)`** (`currencies:115-117`, `securities:160-162`).
- **R10. Create/edit of a record is `useFormModal` + `Modal` + `UnsavedChangesDialog`** (`currencies:49, 341-353`); a deep link to a row uses `useHighlightParam` (`securities:373-381`).
- **R11. A column chooser (`useHiddenColumns` + `ColumnChooserMenu`) belongs to registers only** (TransactionList, InvestmentTransactionList, GroupedHoldingsList). State this, so lists do not gain one ad hoc.
- **R12. No interactive element inside `<a>`**: a back or cancel link is a `Link` styled with `buttonClassName(...)`, never `<Link><Button>`.
- **Open question O1. Count line under a list**: two patterns compete, a centred "N items" for one page (`currencies:403-407`, `securities:507-511`) and `ListBottomPager` `totalLabel` (`transactions:1761-1769`, warranties, investments). Pick one.
- **Open question O2. Summary grid gap** varies (`gap-6`, `gap-4 sm:gap-6`, `gap-3 sm:gap-6`, `gap-4`). Detail pages share `SummaryCardGrid` + `summaryGridClass` (`components/accounts/shared/SummaryCardGrid.tsx:72, 82`); make it the list-page summary row too.

### Dialogs (from the New Transaction dialog)

- **R13. Button row: `FormActions`, right-aligned, Cancel (`outline`, disabled while submitting) first and the primary last, `pt-4` spacing, not sticky** (`components/ui/FormActions.tsx:91-100`, `TransactionForm.tsx:1894-1903`). `SplitSubmitButton` options are "Create" then "Create & New".
- **R14. A form dialog uses `useFormModal` (`pushHistory` + `onBeforeClose`) and renders `UnsavedChangesDialog` beside the `Modal`; the form takes `onDirtyChange` and `submitRef`** (`app/transactions/page.tsx:1504-1533`, `TransactionForm.tsx:410, 1507`).
- **R15. Panel `p-6` (through `className`, keeping `padding="none"`), title `h2 ... mb-4`, form body `space-y-4`.** Hosts of `TransactionForm` share `maxWidth="6xl" className="p-6 !max-w-[69rem]"` (reconcile:696, bills:728, ForeignCurrencyFeesReport:412).
- **R16. Fields: one column on a phone, two or three from `md:` (`grid grid-cols-1 md:grid-cols-2 gap-4`); the whole panel scrolls (`max-h-[90vh]`).**
- **R17. A warning before a save is `ConfirmDialog variant="warning"`** (`TransactionForm.tsx:1928-1937`).
- **R18. A destructive action inside a form section is red text in the section header row** ("Cancel split", `TransactionForm.tsx:1777-1786`), not a danger or primary button.
- **R19. `variant="primary"` is never the selected state of a toggle pair**: use the segmented control.

### Labels and wording

- **R20. One save label: "Save" for a new record and "Save Changes" for an edit** (or the reverse, but one). Today: "Save" 11, "Save changes" 5, "Save Changes" 3, "Update" 1.
- **R21. Required fields carry no marker; neither "*" nor "(required)"** (already implied by the document; say it explicitly, see D23).
- **R22. A placeholder example is "e.g. ..." (56 uses), not "e.g., ..." (26).**
- **R23. Retry is "Try again"** (34 uses, against "Retry" 8 and "Try Again" 2).
- **R24. A failure message starts "Failed to ..." and has no closing period** (247 / 323 uses).
- **R25. A confirmation title is a question ending in "?"** ("Delete this transaction?") or a noun phrase ("Delete Account"); today 35 vs 43, mixed casing. Pick one.
- **R26. Labels have no trailing colon.**
- **R27. The amount's currency is shown once**: by the `CurrencyInput` symbol, not repeated as "({currency})" in the label.
- **R28. Button text in Title Case, as field labels** (today about 102 Title Case vs 96 sentence case; "Add Shares" vs "Add shares", "New Transaction" vs "New transaction" in `share.json:18`, "New rule" in `rules.json:69`).

### Reports, settings, states, destructive actions

- **R29. A report keeps its toolbar mounted while it reloads.** Loading, error and empty states render inside the chart card, below the toolbar, as in `components/reports/SpendingByCategoryReport.tsx:380-394` (its comment: focus in `DateInput` survives a reload). Nine reports do this; 38 return early with a skeleton card.
- **R30. A report error is `ReportError` with `useReportData().reload`** (49 files).
- **R31. A chart/table switch in a report is `ChartViewToggle`** (`SpendingByCategoryReport.tsx:352`, 10 reports).
- **R32. A report date range is `DateRangeSelector` with `showCustom`** (19 files, `SpendingByCategoryReport.tsx:340`). Open question: name a small set of standard `ranges` presets (today 12 different sets).
- **R33. Pie and donut charts use `ChartLegend`; other charts use the recharts default `<Legend />` at the bottom.** One font size for both.
- **R34. A settings section is one card with an `h2 text-lg font-semibold mb-4`; a sub-group heading is `h3 text-sm font-semibold mb-1`** (`components/settings/ProfileSection.tsx:113-114`, `BackupRestoreSection.tsx:345`). The danger zone is the red-bordered card, last on the page (`DangerZoneSection.tsx:166`).
- **R35. A button that saves shows progress with `<Button isLoading>`**, not a label ternary `isSaving ? t('saving') : t('save')` (31+ sites vs 5).
- **R36. A load error outside reports is `EmptyState` + `ExclamationTriangleIcon` + Retry `Button` inside `role="alert"`** (`components/rules/RuleEditor.tsx:35-60`). Open question: an inline error banner has no shared component; 33 files hand-roll it in at least 5 class strings.

- **R38. Every delete or remove asks first with `ConfirmDialog`** (61 renders, no `window.confirm`). An irreversible account-level action (delete account, restore backup, disable 2FA) uses the inline typed/password confirm of `DangerZoneSection.tsx:181`.
- **R39. Feedback after a write is `react-hot-toast` (default import): `toast.success` on success, `toast.error(getErrorMessage(err, t('...Failed')))` on failure, plain `toast()` only for information.**


### Icons, figures, hints, dates, colours, truncation

- **R40. Icons come from `@heroicons/react/24/outline`** (98 files); `24/solid` only for a filled state (the favourite star, `securities/detail/SecurityDetailHeader.tsx:5`). Never an inline `<svg>` that copies a heroicon path.
- **R41. Icon size and spacing: `h-4 w-4` in buttons and rows (`h-3.5 w-3.5` in dense rows, as `ui/row-actions/RowActions.tsx:36-37`), `h-5 w-5` in a header; the icon sits left of the text and the gap is the container's (`inline-flex items-center gap-1`, 68 uses), not `mr-*` on the icon.**
- **R42. Figures are tabular app-wide** (`app/globals.css:113-115`, `body { font-variant-numeric: tabular-nums }`); do not add `tabular-nums` per cell (54 redundant classes today). Amount, rate and quantity columns are `text-right`.
- **R43. A header cell is `Th` / `TH_CLASS`** (`text-xs font-medium text-gray-500 uppercase tracking-wider`); never a hand-copied class string or a local `HEADER_CLASS`.
- **R44. `title` is not an information channel.** An icon-only button has an `aria-label`; information a user needs (a full amount, a rate meaning, a warning) is visible or in an `InfoTooltip`, which works on touch. About 561 `title=` vs 69 `InfoTooltip` today.
- **R45. A date a person reads goes through `useDateFormat()`** (161 files; `useChartDateFormat` for chart axes); a relative time through `useRelativeTime()`. Never `toLocaleDateString`, `toLocaleString`, `Intl.DateTimeFormat` or a date-fns `format` with a fixed English pattern.
- **R46. Meaning colours: `gainLossColor` / `balanceColor` (`lib/format.ts:242, 258`), green and red (not emerald or rose) for amounts; a status pill is `Badge`; a warning is amber, not yellow.**
- **R47. A truncated name carries its full text**: `title` on the truncated element and `break-words` instead of `truncate` on a phone, as `securities/SecurityList.tsx:280` does.
